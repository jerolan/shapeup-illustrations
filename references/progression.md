# Show evolution through a stable visual frame

Use progression when the explanation depends on what changes: discovery becomes understanding, scattered work gains structure, a point advances, parts become integrated, or one component stalls while others move. Progression can also be argumentative: the reader follows a diagram being constructed, questioned, and revised as an explanation unfolds, even when no real-world time passes. Choose an isolated vignette when a single situation already communicates the claim.

## Plan states and transitions

Before generation, specify a small internal state table:

| Explanation beat | What stays recognizable | What changes visibly | Message or implication |
| --- | --- | --- | --- |
| Establish | Shared scene, list, or diagram | Starting configuration | What to understand or question first |
| Develop or revise | Same visual artifact and identities | An added item, edit, boundary, position, connection, or state mark | Why the change matters at this point |
| Reassess | Same frame and entity mapping | Next supported transformation | What now works, remains unresolved, or needs reconsideration |

Use as many states as the idea requires to expose a meaningful transition. Two states can explain a contrast; an intermediate state helps explain how the change happens. Do not invent events or claim completion when the source only supports partial progress. Progress can branch, stall, or reverse when the supplied account says so.

## Guide the reader through an evolving artifact

Treat the image sequence like an explanation unfolding on a shared sheet of paper. Establish enough structure to orient the reader, reveal or modify the next relevant element, then state what this changes in the reasoning. The stable artifact lets the reader compare without reconstructing the entire idea.

Choose from these drawing operations as the argument requires: add an item, append a field, check a box, strike out a rejected option, rewrite a label, move an item into a group, split a list, connect two parts, or redirect an arrow. Preserve unaffected content so the operation is apparent. Keep a crossed-out alternative legible when seeing the rejected choice is part of the explanation; otherwise remove it cleanly in the next state.

Pair each meaningful state with a short observation, question, or conclusion when it helps guide attention. Put it beside the drawing, in a small callout, or in adjacent article prose according to the requested deliverable. Anchor the message near the affected region. Messages explain the consequence; labels identify objects. Use the user's wording or derive a faithful short statement from their source rather than adding a headline to every frame.

Let the message stay the same when the conclusion has not changed. For example, two states can both say that nothing is usable: first one layer has completed pieces, then both layers have pieces that do not align. Only an integrated slice supports the changed conclusion that a usable piece exists. More checkmarks alone do not justify that conclusion. This pattern can teach why an apparently promising change is insufficient before showing the decisive one.

## Lists that develop with the explanation

Keep the list's container, item identities, and unaffected order recognizable. Introduce entries when the explanation discovers or defines them; distinguish a new entry from a completed one. Show edits as edits, regrouping as regrouping, and completion as a state change. A removed item can be canceled, moved, or completed; make its meaning evident rather than using disappearance for all three.

For a proposed action sequence, show how adding a field exposes a question, then how moving an option or redirecting a connection resolves that question. For work lists, a valid sequence might discover entries, organize them into scopes, complete one coherent group, and uncover more work elsewhere. Select only the operations relevant to the supplied account instead of forcing a fixed empty-to-full-to-done story.

## Choose the carrier of change

- **Movement:** move an identifiable dot along the same path or hill. Keep the path, direction, and endpoint meanings stable. If earlier positions remain in one diagram, distinguish previous states with a pale trail or step markers; make it clear these are successive positions of one item.
- **Accumulation:** preserve existing items and add newly discovered ones. Show that discovering more work can coexist with progress rather than depicting every advance as a shrinking list.
- **Revision:** retain the base drawing and mark changed words, removed options, new fields, or rerouted arrows with a restrained accent. Use the same accent role across steps; an addition color does not automatically mean an error.
- **Decomposition:** transform a shared outline from undivided space into meaningful regions. Keep its silhouette recognizable and show which parent region becomes which children.
- **Integration:** keep the same layers and align a growing completed portion across them. The completed marks must refer to working pieces described by the source.
- **Parallel evolution:** repeat the same frame with several identified points. Preserve each point's label and color across snapshots. A point that stays still can communicate a blockage without changing its identity.
- **Human narrative:** repeat the same people, props, and viewpoint while actions, posture, or the shared drawing change. Connect the reaction to the visible event rather than relying on new dialogue alone.

These are mechanisms, not a fixed catalog of book metaphors. Invent an appropriate shared frame for the user's subject.

## Make continuity do explanatory work

Keep framing, orientation, scale, landmark positions, linework, and entity identities stable unless changing one is the point. Use one principal change per transition, with coordinated secondary changes only when necessary to explain it. Give each accent a consistent role; identity colors track entities, while completion can use checkmarks or another separate state cue.

The viewer should be able to point to the changed mark and explain what advanced. Merely numbering unrelated pictures or replacing their captions does not show evolution.

Distinguish conceptual position from measurement. A hill can show uncertainty becoming resolved without claiming elapsed time, percent completion, or a delivery forecast. Keep quantitative axes, timestamps, percentages, and distances proportional only when supported by supplied data.

## Deliver one image or a distributed sequence

- **One requested image:** put the necessary snapshots in a readable strip or grid, or show a clear trail within one diagram. Use spacing, small step labels, or purposeful arrows to establish reading order. Keep labels legible rather than packing in every state.
- **Article or documentation sequence:** place successive states next to the paragraphs that introduce the change. Maintain the shared visual frame across separate image files; name them in reading order and give each alt text describing its state and transition.
- **Separate generated files:** use the first selected generated frame as the continuity reference for later states, along with the state table. Describe the changes explicitly and preserve already correct geometry. Inspect the files together to catch drift.

Keep the requested image count. A request for progression does not itself request animation; render the change through static visual states unless animation is explicitly requested and supported by the generator.

## Four-panel conversations

When the user requests four quadrants or a four-panel conversation, generate one bitmap with a 2×2 grid. Read top left, top right, bottom left, then bottom right. Use whitespace gutters or light hand-drawn dividers. Keep the same people, shared artifact, viewpoint, and color roles recognizable across all four panels.

Give each panel one explanatory beat. An idea, an objection, a revision, and an agreement work when the source supports that story. A fourth panel can instead leave an open question or next experiment. Do not manufacture agreement or completion to fill the layout.

Place short dialogue in speech bubbles or small text messages within the corresponding panel. Make the speaker unambiguous and put the bubble near that person. Use concise wording faithful to the supplied conversation, or preserve exact strings when requested. Add a brief in-panel explanatory note only when the visual change and dialogue leave a necessary transition unclear. Keep captions outside the image for alt text and supporting documentation, not as a replacement for requested in-panel text.

Develop the idea in the drawing as well as the dialogue: question an existing mark, remove an option, narrow a boundary, or try the revised artifact. Four unchanged scenes with different messages do not show development. Resolve palette and contrast using [style-dna.md](style-dna.md) before generation.
